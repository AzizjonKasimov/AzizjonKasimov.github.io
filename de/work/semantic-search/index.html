Semantische KI-Suche für Autoteile

Käufer und Lieferanten mussten das genau passende Teil für ein bestimmtes Auto mit einfachen Worten finden können, und das in mehreren Sprachen. Ich habe die Suche von Anfang bis Ende gebaut, dazu eine Testsuite, die belegte, dass sie die Vorgabe von 95 % Genauigkeit erfüllte.

Meine Rolle
Allein zuständig für KI/ML: Design, Embeddings, Entitätserkennung, LLM-Schritte, Evaluation und Produktivbetrieb lagen bei mir.
Ergebnis
Mindestens 95 % Genauigkeit im vorgegebenen Test mit 3.000 Teilen. Das F&E-Projekt wurde genehmigt.
Stack
Python, Django REST Framework, Weaviate, spaCy, OpenAI API (GPT-4o-mini), Celery, PostgreSQL, AWS S3, React
Größenordnung
Ein Katalog mit über 2 Mio. Teiledatensätzen und über 300.000 durchsuchbaren Angeboten (Kia, Hyundai, SsangYong, Chevrolet)

Das Problem

Menschen beschreiben dasselbe Teil auf viele Arten: „headlight“ oder „head lamp“, umgangssprachliche Namen oder andere Sprachen. Die richtige Antwort ist aber eine Teilenummer für ein ganz bestimmtes Auto: Marke, Modell, Baujahr, Kraftstoff, Getriebe, Generation und Seite (links oder rechts, vorne oder hinten).

Starre Stichwortfilter kamen damit nicht zurecht. Das Unternehmen brauchte eine Suche in natürlicher Sprache, die mit hoher Präzision das richtige Teil liefert. Außerdem musste sie einen formalen Genauigkeitstest für ein F&E-Projekt bestehen.

So läuft eine Suchanfrage ab

Was ich gebaut habe

  • Kern der Vektorsuche. Ich habe den Teilekatalog in Weaviate eingebettet und den Suchdienst mit Django REST Framework gebaut. Den Text, der eingebettet wird (Feldbezeichnungen, Einbauseite, Baujahr und kuratierte Synonyme), habe ich so gestaltet, dass der Recall steigt.
  • Entitäten als harte Filter. spaCy zieht strukturierte Fakten aus einer Freitext-Anfrage und macht daraus exakte Filter. Die Vektorsuche kümmert sich um die Formulierung, die Filter sorgen dafür, dass Auto und Seite stimmen.
  • Zwei Suchmodi. Produktsuche für Käufer. Automatischer Abgleich für Lieferanten: Ein hochgeladenes Teil wird Katalogdatensätzen zugeordnet, und jede eindeutige Teilenummer wird zu einem eigenen Treffer.
  • Mehrsprachige Anfragen. Anfragen, die nicht auf Englisch sind, laufen durch einen LLM-Schritt. Der Wechsel von GPT-3.5-Turbo zu GPT-4o-mini brachte bessere Qualität bei geringeren Kosten, und die Sprachprüfung hält LLM-Aufrufe auf einem Minimum.
  • Relevanz-Tuning. Ein LLM-Re-Ranker entfernt klar falsche Treffer. Ein Alias-System für Teilenamen (zum Beispiel „headlight“ → „Head Lamp Assembly“) erhöhte die Genauigkeit bei alltäglichen Formulierungen.
  • Anbindung ans Frontend. Ich habe den Shop und die Admin-Tools (React/TypeScript) an die Such-APIs angebunden: Filter fließen in die Anfrage ein, Treffer füllen Formulare automatisch aus, und Ergebnisse werden nach Relevanz sortiert, mit einer Konfidenzschwelle.

Genauigkeit messen

Die Genauigkeit musste gemessen und nicht geschätzt werden. Ich habe eine interne Testseite gebaut, die dieselbe Pipeline wie die Produktivsuche auf einem festen, kuratierten Testdatensatz ausführt.

  • Metriken: accuracy@1 und accuracy@3, Precision, Recall, F1, eine Konfusionsmatrix und Kreuzvalidierung.
  • Wiederholbare Läufe: automatisch oder manuell. Jeder Lauf hält fest, wer ihn gestartet hat und ob die LLM-Vorverarbeitung aktiv war.
  • Von Grund auf sicher: Testdaten liegen in eigenen Collections, mit Schutzmechanismen, damit ein Test nie Produktionsdaten berühren kann.
  • Fehleranalyse: Ich habe Fälle ohne Treffer auf veraltete Testobjekte, Abweichungen zwischen SKU und Katalog, kollidierende Entitätsmuster und die Behandlung von Karosseriefarben zurückgeführt und jeden davon behoben.

Ergebnisse

  • 95 %+Genauigkeit auf dem vorgegebenen Evaluationsdatensatz mit 3.000 Teilen
  • GenehmigtF&E-Projekt, nach Erreichen der Genauigkeitsvorgabe
  • 300.000+durchsuchbare Angebote, auf einem Katalog mit über 2 Mio. Teiledatensätzen

Die Suche ging für Käufer und Lieferanten in Produktion. Außerdem habe ich die automatisierten Genauigkeitstests in der Produktivumgebung ausgeführt und die gefundenen Probleme behoben.
