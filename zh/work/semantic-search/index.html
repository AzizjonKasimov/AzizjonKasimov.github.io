汽车零部件 AI 语义搜索

买家和供应商需要用普通的词语、以多种语言，为特定车型找到准确的零件。我端到端地构建了这套搜索，并开发了一套测试套件，证明它达到了 95% 的准确率要求。

我的角色
公司唯一的 AI/ML 工程师。负责设计、向量嵌入、实体识别、LLM 步骤、评估和生产上线。
成果
在规定的 3000 个零件测试中准确率达 95%+。研发项目已获批准。
技术栈
Python、Django REST Framework、Weaviate、spaCy、OpenAI API（GPT-4o-mini）、Celery、PostgreSQL、AWS S3、React
规模
超过 200 万条零件记录的目录，以及超过 30 万条可搜索的商品信息（Kia、Hyundai、SsangYong、Chevrolet）

问题

人们对同一个零件有很多种说法：“headlight”或“head lamp”、非正式的叫法，或者其他语言。但正确答案只有一个：一辆确切车型对应的一个零件编号，涉及品牌、车型、年份、燃料、变速箱、代次和位置（左或右、前或后）。

僵硬的关键词过滤无法应对这种情况。公司需要一种能以高精度返回正确零件的自然语言搜索，而且它还必须通过研发项目的正式准确率测试。

我构建了什么

  • 向量搜索核心。我把零件目录嵌入到 Weaviate 中，并用 Django REST Framework 构建了搜索服务。为了提高召回率，我设计了用于嵌入的文本（字段标签、零件位置、车辆年份和精选同义词）。
  • 实体作为硬过滤条件。spaCy 从自由文本查询中提取结构化信息，并把它们变成精确的过滤条件。向量搜索负责处理措辞差异，过滤条件则确保车型和位置正确。
  • 两种搜索模式。为买家提供商品搜索。为供应商提供自动匹配：上传的零件会与目录记录进行匹配，每个不同的零件编号作为一条单独的结果。
  • 多语言查询。非英语查询会经过一个 LLM 步骤。从 GPT-3.5-Turbo 换成 GPT-4o-mini 后，质量更好、成本更低，而语言检测让 LLM 调用保持在最低限度。
  • 相关性调优。LLM 重排序器会剔除明显错误的结果。零件名称别名系统（例如“headlight” → “Head Lamp Assembly”）提高了日常说法的准确率。
  • 前端对接。我把 React/TypeScript 商城和后台工具接入了搜索 API：筛选条件会传入查询，匹配结果会自动填写表单，搜索结果按相关性排序并设有置信度阈值。

衡量准确率

准确率必须靠测量，而不是靠猜测。我构建了一个内部测试页面，在一个固定的、精心整理的测试集上运行与生产搜索相同的流水线。

  • 指标：accuracy@1 和 accuracy@3、精确率、召回率、F1、混淆矩阵和交叉验证。
  • 可重复运行：自动或手动运行。每次运行都会记录运行者，以及是否开启了 LLM 预处理。
  • 安全设计：测试数据存放在独立的集合中，并设有防护措施，确保测试绝不会触碰生产数据。
  • 错误分析：我把“无结果”的情况追溯到过期的测试对象、SKU 与目录不匹配、相互冲突的实体模式以及车身颜色的处理问题，并逐一修复。

结果

  • 95%+在规定的 3000 个零件评估集上的准确率
  • 已获批准研发项目，在达到准确率要求之后
  • 30 万+可搜索的商品信息，基于超过 200 万条零件记录的目录

该搜索已面向买家和供应商在生产环境上线。我还在生产环境中运行了自动化准确率测试，并修复了测试发现的问题。
